# Solver versions and access

The public review package supports numerical checks, figure regeneration, exact coordinate reconstruction, and verification of an authorized saved tour. It also records solver provenance so reviewers can identify the versions used for historical computations. Running new timed solves requires additional material.

| Component | Public information and access |
|---|---|
| C, M, K | The paper and supplement define the parent search, selection, GPX2 placement, seed mapping, full charging, and continuation. The historical R4 binding uses the project P5 and P5-resume Windows binaries and the native GPX2 bridge. Registered example parameter hashes, binary hashes, launch roles, version and deadline facts are in the supplementary material and the adjacent version CSV. The exact project/upstream sources, derived binary and full historical build environment require separate rights and access confirmation. |
| Author LKH-GPX2 and LKH-POP | LKH 3.0.14 with the documented Ascent64 compatibility change. The supplement provides distinct settings and the registered executable, example configuration and compiler hashes. Obtain upstream separately under its applicable terms. The upstream software is not equivalent to the particular compatible build by version name alone. |
| GA-EAX | The historical R4 build uses the Normal Windows compatibility variant and a separate observer and stopping wrapper. Earlier original and supplemental records use different wrappers. The engineering receipts identify the native binary hash and execution scope. The [upstream source commit](https://github.com/nagata-yuichi/GA-EAX/tree/015dfbe9f267230f78787bd244af393ffc018900) is separately available under its stated licence. The exact modified build, associated wrappers and redistribution of the complete local toolchain have separate conditions. |
| Windows runtime | The source Windows environment used a CPU0 Job and a per-process 4 GiB commit limit for the recent engineering suite. It logged owned process exits, system paging and memory and verified delivered tours. The 90-second and 30-second protocols, including their distinct cutoff sequences, are documented in the manuscript, supplement and proposed plans. These protection and evidence paths form part of the experimental environment; pseudocode alone cannot reproduce them. |

[Methods and configuration tables](../manuscripts/en/Supplementary_Methods.pdf) · [Example hashes](../manuscripts/en/version_hashes.csv) · [LKH author site](https://keldhelsgaun.github.io/) · [GA-EAX author distribution](https://github.com/nagata-yuichi/GA-EAX).

For an authorized reconstruction, request the original source or audited local patch set, exact `run.par` and `resume.par` files, native version binding, the same compiler and flags recorded by the build, Windows runtime, and supervision scripts. Compare the built SHA256 to the original receipt or report a different build. Start by matching the map bytes and running the independent tour verifier. Historical timings are platform-specific. The public package has no claim of a new end-to-end reproduction on a clean recipient machine.
